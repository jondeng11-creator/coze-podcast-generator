# Coze 语音播客工作流搭建指南

本 skill 依赖一个你自己搭建的 Coze「语音播客」工作流。以下步骤和踩坑来自真实
部署经验，照着做能少走弯路。

## 一、创建语音播客工作流

1. 打开 Coze（coze.cn）→ 进入你的空间 → 新建「工作流」。
2. 默认带「开始」节点，保留。
3. 添加「语音播客」插件节点（插件库搜索「语音播客 / genPodcastURL」，
   默认生成一男一女双主播对谈）。
4. 配置插件输入：
   - `input_text`：**必须引用「开始」节点的输入字段**（如 `开始.input`），
     不能留空、也不能手填静态文本，否则报错
     `input content can not be empty`。
   - `use_head_music`：可选，是否加插件自带片头音效（轻量，非全程 BGM）。
5. **结束节点**：必须接「结束」节点，返回值字段名填 `podcast_url`，
   映射到语音播客节点的输出。
   - ⚠️ **严禁使用「输出」节点**。含「输出」节点的工作流，API 调用会返回
     `data` 为空、`usage` 全 0（网页试运行却正常）——这是 API 硬限制。
6. 右上角「发布」工作流，发布后从编排页 URL 拿到：
   - `workflow_id`（`workflow_id=` 后的数字）
   - `space_id`（`space_id=` 后的数字，建议填，避免跨空间权限报错）

## 二、获取 PAT（个人访问令牌）

进入 Coze「个人设置 → API 管理 → 创建令牌」，复制以 `pat_` 开头的令牌。

## 三、调用方式（本 skill 已封装）

- `POST https://api.coze.cn/v1/workflow/run`
- 鉴权：`Authorization: Bearer <PAT>`
- 请求体：`{"workflow_id": "...", "space_id": "...", "parameters": {"input": "<文字稿>"}}`
- 返回 `data` 是 JSON 字符串，其中 `podcast_url` 即音频直链
  （**有效期约 3 天，需尽快下载保存**——脚本已自动下载到本地）。

## 四、关键限制（务必告知使用者）

1. **只能长文整集**：插件会把整段输入重写为双主播对谈。喂「短文 / 固定
   开场白」会被当成话题，自动扩写成一整集跑题内容。因此本 skill 刻意只生成
   正文单集，不要试图用插件拼固定开场/结束语。
2. **字数上限**：`input_text` 约 ≤ 15000 字。超长需分段或精简。
3. **无 BGM**：插件本身只提供可选片头音效，不提供全程 BGM。需要 BGM 得本地
   用 ffmpeg 混入（本纯净版不含）。
4. **直接贴正文**：插件会处理成口语对谈，无需手工改成对话稿。

## 五、排错速查

| 现象 | 原因 / 解决 |
|---|---|
| `input content can not be empty` | `input_text` 没连到「开始」节点 |
| 返回 data 空、usage 全 0 | 工作流含「输出」节点，删掉改「结束」节点重新发布 |
| 很久没反应 | 音频生成较慢，单次最长约 10 分钟，脚本已设 600s 超时 |
| 链接打不开 / 403 | 直链已过期（约 3 天），重新生成并下载 |
